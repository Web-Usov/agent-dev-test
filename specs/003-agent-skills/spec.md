# Спецификация: skills-based workflow

Статус: draft

Issue: #3

## Контекст

Шаблон уже задаёт spec-first процесс через `AGENTS.md`, документацию и GitHub Actions, но правила работы агента пока собраны в одном большом файле. Нужен компактный набор reusable skills, который можно одинаково хранить в Git, использовать в Codex и устанавливать в ChatGPT Web.

## Цель

Сделать 4 базовых workflow skill, которые задают режим работы агента, а предметные capability skills выбираются автоматически по необходимости.

## В scope

- `dev-core` для clarification, scope, spec, plan и tasks;
- `dev-build` для реализации согласованного решения;
- `dev-debug` для диагностики и исправления дефектов;
- `dev-review` для независимого review, read-only по умолчанию;
- `.agents/skills/` как канонический Git-источник;
- автоматический выбор минимального набора вспомогательных skills по доступным `name`/`description`;
- упаковка каждого skill в отдельный ZIP для установки/обновления в ChatGPT Web;
- CI-проверка структуры skills;
- документация различий между GitHub, Codex и ChatGPT Web.

## Не входит

- отдельный глобальный репозиторий персональных capability skills;
- автоматическое обновление навыка в аккаунте ChatGPT;
- API-интеграция для публикации skills;
- привязка к конкретному стеку приложения.

## Пользовательские сценарии

### Новая функция

Пользователь описывает идею без выбора специализированных навыков. Агент выбирает `dev-core`, уточняет только существенные неизвестности и доводит задачу до согласованных `spec.md`, `plan.md`, `tasks.md`.

### Реализация

Пользователь просит реализовать Issue или уже подготовленную задачу. Агент работает в `dev-build` и при необходимости автоматически подключает доступные capability skills, например frontend или Playwright.

### Баг или CI failure

Агент работает в `dev-debug`: сначала собирает evidence и root cause, затем делает минимальный fix и regression test.

### Review

Агент работает в `dev-review`, не меняет код по умолчанию и возвращает findings, привязанные к требованиям и diff.

## Функциональные требования

1. Явно указанный пользователем workflow skill имеет приоритет над автоматическим выбором режима.
2. Если режим не указан, агент выбирает один базовый workflow skill по намерению задачи.
3. Каждый workflow skill перед существенной работой оценивает доступные вспомогательные skills и выбирает минимальный релевантный набор.
4. Отсутствующий или недоступный auxiliary skill не должен блокировать работу, если задача может быть выполнена без него.
5. `AGENTS.md` содержит bootstrap, invariants и routing, но не дублирует подробные workflow.
6. Каждый базовый skill соответствует формату `SKILL.md` с обязательными `name` и `description` в YAML frontmatter.
7. Версия skill хранится вне обязательного frontmatter, чтобы не расширять минимальный переносимый формат.
8. Репозиторий является источником истины; установленная в ChatGPT копия считается производной.
9. Упаковка skill не включает secrets, `.git` и посторонние файлы.

## Нефункциональные требования

- stack-agnostic;
- русскоязычные инструкции и GitHub-тексты;
- минимальный контекст через progressive disclosure;
- отсутствие произвольного shell из Issue/PR/comment;
- переносимость между средами, поддерживающими Agent Skills.

## Критерии приёмки

- В `.agents/skills/` есть 4 базовых skill.
- CI валидирует наличие `SKILL.md`, `name`, `description` и совпадение `name` с каталогом.
- Есть команда упаковки skills и GitHub Actions artifact с отдельными ZIP.
- README и процесс разработки объясняют, как использовать skills в Codex и ChatGPT Web.
- В `AGENTS.md` описан routing и automatic auxiliary skill discovery.
- `dev-review` не исправляет findings без отдельной команды пользователя.

## Открытые вопросы

Нет блокирующих. Автоматическая синхронизация GitHub → ChatGPT намеренно откладывается.
